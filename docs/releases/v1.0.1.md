# Assertiva v1.0.1 — Dogfood Reliability Fixes

Released on 2026-11-16 as a GitHub Release, with wheel, sdist and `SHA256SUMS.txt`. **It is not published on PyPI.**
Python 3.11 or newer. Patch release over [1.0.0](v1.0.0.md): no new command, option or report field is required, and
reports from 1.0.0 keep their meaning.

All four fixes come from dogfooding Assertiva on SotuHire (a FastAPI + Vite/Vitest project) in November 2026.

## Fixes

- **Read-only guarantee with linked `node_modules`.** With `--mutate` on a Vite/Vitest project, Vitest wrote its
  cache (`node_modules/.vite`) into the audited project through the dependency link in the disposable copy; the
  read-only guard then rejected the whole audit after the run (exit 3, no report). Adapters now declare the cache
  entries their runner writes inside installed dependencies (`tool_cache_entries()`; Node adapters: `.vite`,
  `.vitest`, `.cache`, `.vite-temp`). Such a directory becomes a real directory in the copy with its other children
  linked. The core still names no tool (`link_installed(..., local_only=...)`).
- **Collection errors caused by an unprepared environment** are attributed to it: `NATIVE_COLLECTION_ERRORS` carries a
  `dominant_cause` with origin `ENVIRONMENT` when the only missing modules are third-party ones and the environment
  was not prepared.
- **Pre-commit hooks from known remote repositories** (`astral-sh/ruff-pre-commit`) are attributed to the tool they
  run, removing a false `LOCAL_CHECK_NOT_OBSERVED_IN_CI` when CI runs the same tool.
- **Windows self-tests:** process cleanup and a lease-release assertion no longer fail for test reasons.

## Validation

- Unit suite on Python 3.12 (1,161 passed, 6 skipped) and 3.11 (1,161 passed); integration suite on Python 3.12
  (193 passed, 12 skipped); `scripts/validate_repo.py`; ruff.
- CI on the release commit: `validate`, Windows and Python 3.11 compatibility (conditional jobs skipped by their
  path filters).
- The core-independence test (`test_core_modules_do_not_name_tools`) is unchanged and passes.

## Known limitations

Unchanged from [1.0.0](v1.0.0.md#known-limitations).

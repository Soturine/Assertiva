# Assertiva v1.0.0 — Evidence-Grounded Test Assurance

Released on 2026-11-13 as a GitHub Release, with wheel, sdist and `SHA256SUMS.txt`. **It is not published on PyPI.**
Python 3.11 or newer. The only runtime dependency is PyYAML.

Assertiva is an agent-led test-assurance tool: a Skill that investigates what a project's tests really prove, and a
deterministic engine that collects, runs (in disposable copies), normalizes and reports evidence. 1.0.0 is a release
about the quality of that evidence. It makes clear which code a run tested, with which runner, at which revision,
with what scope and result, and what was imported rather than executed.

## Highlights

- **Code identity for every Python runner.** pytest, unittest and Django runs record where the project's modules were
  imported from (`SOURCE_TREE`, `INSTALLED_ARTIFACT`, `MISMATCH` or `UNKNOWN`), observed inside the test process.
- **Installed-artifact qualification that proves itself.** Tests run against the built wheel with the project's own
  runner (pytest or unittest), and a green run counts only when every project module it loaded came from the
  installed artifact.
- **Mutation testing with honest scope.** `--mutate-tests` works under unittest. An empty selection, or one that cannot
  be loaded, stops the run at the selection stage (`MUTATION_RUN_NOT_COMPLETED`); it is never a passing baseline. The
  baseline's own test count is recorded.
- **Imported results stay imported.** Results read from JUnit, CTRF or Allure files are counted as `imported_*` and
  reported as `IMPORTED_TEST_RESULTS_FAILING`, never as executions by Assertiva.
- **CI parity per check.** Each local check is `COVERED`, `POSSIBLY_COVERED` (with the traceable chain through
  `package.json` scripts and repository scripts) or `NOT_OBSERVED`. An unrelated opaque CI step never lowers a gap.
- **Opt-in CI gate.** `assertiva audit --fail-on test-failure|not-passing|imported-failure|artifact|high-findings|findings`
  exits 1 and writes its decision to the report's `gate` field. Without it, exit codes are unchanged.
- **Safer diagnostics.** Collection causes are classified and sanitized (credentials, token shapes, e-mail addresses,
  absolute paths) before they are bounded. A failed cleanup is declared with its real cause, without exporting the
  temporary path.
- **Conservative unittest detection** for projects that declare no runner, and `FILTERED_LOOP_ASSERTION` for
  assertions behind a filter over loop cases.

## Observable report changes

`imported_*` metrics; the new codes `IMPORTED_TEST_RESULTS_FAILING`, `MUTATION_RUN_NOT_COMPLETED` and
`LOCAL_CHECK_POSSIBLY_RUN_BY_CI_SCRIPT`; per-check CI states; unittest/Django identity; the optional `gate` field; the
inferred unittest runner. Details and what to change: [docs/MIGRATION_V1.md](../MIGRATION_V1.md).

## Install

Download the wheel from the GitHub Release, check it against `SHA256SUMS.txt`, then:

```bash
python -m pip install assertiva-1.0.0-py3-none-any.whl
assertiva --version        # assertiva 1.0.0
assertiva audit path/to/project
```

The Skill is `SKILL.md` and `references/` in this repository. Put or link that directory where your agent loads
skills; installing it changes no configuration.

## Known limitations

- **Agent-led evaluation:** 8 cases, single runs, with agent and judge from the same model family (Haiku 5.5 and
  Sonnet 5.5), so this is not an independent qualification. Judge verdicts: **6 PASS, 2 REVIEW, 0 FAIL**.
  `FISCAL_TEMPORAL_ORACLE_FALSE_GREEN` stays REVIEW. `AGENT_PROFILE_MOVE_UNDO_FALSE_GREEN` does not meet its frozen
  pass condition in the operator's reading. The owner accepted both as documented limitations of this release
  ([V1_AGENT_EVALS](../assurance/V1_AGENT_EVALS.md)).
- Tests against an installed wheel can fail because a project's tests read the source tree. The report shows FAIL,
  and recognizing such tests automatically is deferred.
- The static `--dependencies` inventory does not flag undeclared imports. Only the `--execute` artifact qualification
  checks that closure.
- There is no native executor for .NET, Go, Rust, PHP, Ruby or Lua (portable results only), and no PIT through
  Gradle. The deferred items are listed in [ROADMAP](../../ROADMAP.md).
